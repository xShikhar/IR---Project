# TurnTrace 2 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. The user requested continuous end-to-end execution after the design discussion.

**Goal:** Deliver visible, tested improvements to the existing conversational IR engine.
**Architecture:** Preserve midterm modules, add independent v3 search and workspace services, expose API, build React workspace, evaluate with honest label coverage.
**Tech Stack:** React 18, Vite, Express, Node ESM, node:test; optional local embedding inference.
**Spec:** docs/superpowers/specs/2026-11-21-turntrace-2-design.md

## Global constraints
Work only in IR-Project. Preserve midterm behavior and data identifiers. No runtime access to gold labels. All UI controls must work. Preview must not mutate session memory. Model availability and incomplete judgments must be visible. No hosted publication or external messages.

## Review focus
Cross-session contamination; preview/retry duplicate turns; ambiguous multi-topic pronouns; filters leaking through fusion; absent model/network; empty results and feedback undo.

## Task 1: Search service
- [ ] Write and run behavioral tests for weighted ranking, filters, snippets, diversity and feedback.
- [ ] Implement createSearchService contract in server/src/v3/search.js, preserving original modules.
- [ ] Implement cached semantic retrieval and preparation script with an explicit availability state.
- [ ] Run focused tests and document inference limits.

## Task 2: Workspace and API
- [ ] Write and run tests for branch creation/resumption, clarification selection, undo and immutable preview.
- [ ] Implement workspace service and validated Express routes.
- [ ] Connect baseline comparison and two-subject evidence comparison.
- [ ] Run original and new API tests.

## Task 3: React workspace
- [ ] Implement topic navigation, chat, evidence cards, context correction and feedback against the specified API.
- [ ] Implement side-by-side baseline and subject comparison, scenarios, experiments and export.
- [ ] Build and verify in browser at desktop/mobile widths, including failure/loading states.

## Task 4: Evaluation and delivery
- [ ] Add independent behavior scenarios and v3 runner without altering frozen artifacts.
- [ ] Compute measured results and judgment coverage, export pooling sheets.
- [ ] Write setup/demo/research documentation and verify report outputs.
- [ ] Run integration suite, production build, browser walkthrough and package source+dataset.
