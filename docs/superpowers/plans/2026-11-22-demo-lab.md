# Demo lab implementation plan

The user requested an executable presentation tab covering the project features and a full working-app verification. Implement directly in the existing React/Node workspace, without changing the retrieval algorithm or published benchmark numbers.

- [x] Add a corpus-backed tour catalog with ordered actions, observable checks, presenter notes, prerequisites and duration.
- [x] Write failing controller tests; implement a framework-independent runner for real search, clarification, preview, feedback/undo, methods, context audit, comparison and evidence inspection actions.
- [x] Add a dedicated Demo lab navigation tab, catalog filters and persistent walkthrough controls across the existing views.
- [x] Start each tour in a separate session and provide restart/exit with restoration of the original workspace; prevent double submissions and do not advance failed steps.
- [x] Verify every scripted tour against the real local API, add browser tests for launch, progress, clarification, restart/exit and responsive layout.
- [x] Run the full original/new test suites, production build and browser workflows; inspect screenshots, fix observed defects, update the demo documentation and leave the app running.

Design decision: reuse existing feature views for live evidence, with a persistent step guide rather than duplicating the search/comparison interfaces inside the catalog. Tours are separate from the frozen evaluation conversations and contain no fabricated grades or effectiveness claims.
